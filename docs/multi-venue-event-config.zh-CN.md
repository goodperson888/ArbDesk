# 多平台事件配置说明

当前版本内置 BTC 的 5 分钟和 15 分钟事件。事件统一由主体、周期、开始时间、结束时间、结算来源和结果集合生成稳定 `eventId`；平台自己的市场 ID 通过映射表关联到这个事件。

## 当前内置事件

```ts
{
  category: 'CRYPTO',
  subject: 'BTC',
  interval: '5m' | '15m',
  settlementSource: 'CHAINLINK-BTC-USD',
  outcomes: ['UP', 'DOWN']
}
```

5m 和 15m 即使标的是同一个 BTC，也会生成不同的事件 ID。开始和结束时间必须完全一致，不能把相邻窗口或不同周期的市场配成一条路线。

## 平台映射原则

每个平台适配器只上报自己的市场字段：

```text
venueId + marketId + eventId + outcomeId + quote/depth
```

机会引擎只比较同一个 `eventId` 下的平台报价，不直接解析平台 URL、slug 或页面文案。平台没有完整成交回读能力时，即使能提供价格和深度，也只能显示观察路线。

当前能力状态：

| 平台 | BTC 5m | BTC 15m | 执行状态 |
| --- | --- | --- | --- |
| MEXC | 已接入 | 已接入 | 保留成熟链路 |
| Polymarket | 已接入 | 已接入 | 保留成熟链路 |
| Kalshi | 不纳入 | 已接入 | 双腿人工确认，Kalshi FOK 第二腿 |
| Limitless | 观察 | 观察 | 只读 |
| Predict.fun | 已接入 | 已接入 | API 或已登录页面双腿执行（人工监督） |
| Gate | 已接入 | 已接入 | 页面双腿执行（人工监督） |

## 以后加入 ETH

加入 ETH 时，核心套利代码不需要增加 `if (asset === 'ETH')`。只需：

1. 在事件目录注册 `subject: 'ETH'` 的 5m/15m 事件。
2. 在各平台适配器中把平台市场映射到对应 `eventId`。
3. 为该平台补充结算源和结果集合校验测试。
4. 先以观察模式运行，确认行情、深度、费用和成交回读后，再单独打开该路线的实盘门禁。

如果两个平台的结算来源、平价规则或结果语义不同，系统会标记为条件型/观察路线，不会自动执行。

## 执行和恢复

双腿执行使用路线级幂等键。默认顺序是首腿成交后再提交第二腿；部分成交、网络超时或状态未知会持久化为恢复会话，软件重启不会自动重发未知订单。人工核对两边订单后，才能将会话标记为已恢复。
